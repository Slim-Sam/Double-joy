# Список задач — фильтр «кадр-кадр» (frame-to-frame pixel-delta) для алгоритма Сверки

> Источник: эмуляция `frame_delta_emu/` (4 сценария × 120 триалов).
> Результат: FP падают ~100–150×, FN растут минимально (0.00→0.06–0.16).
> Правило: это **фильтр уверенности вниз по конвейеру**, не замена модели сравнения (`layersEqual`) и не замена causal engine (H0–H4).

## Приоритет 1 — ядро фильтра (базовый функционал)

- [ ] **Хранить предыдущий кадр** (1–2 кадра, 540px, ~1–2 MB) в `AppState` (или отдельном keeper). Не хранить всю историю — только последний кадр и, возможно, кадр с 0° для подстраховки.
- [ ] **Выравнивание кадров перед delta** — оценить смещение (phase correlation / `cv2.phaseCorrelate` или повторное использование геометрии `fitBoardCamera`) и синхронно сдвинуть предыдущий кадр на текущую сетку.
- [ ] **Per-cell pixel-delta по незанятым пикселям** — использовать маска `claimed[]` (unclaimed pixels) для каждой клетки, вычислить MAD между кадрами. Не использовать pixel-delta по полной площади клетки (окклюзированные регионы дают ложный delta).
- [ ] **Калибровка threshold (eps)** — сконфигурировать `eps` по «доверенным» клеткам (клетки, где базовое чтение CV совпадает с моделью и клетка не окклюзирована): 95-й процентиль MAD × коэффициент (например, 1.15), ограничение в разумных пределах.

## Приоритет 2 — правила безопасности

- [ ] **Не супрессировать diffs окклюзированных клеток** — если `occludedCellBlockers` содержит клетку, pixel-delta для неё бессмысленна (пиксели заняты чужой башней); diff остаётся как есть.
- [ ] **Не использовать pixel-delta как гарант «клетка не тронута»** — фильтр только понижает вес срабатывания CV (шумоподавление), не пропускает клетку из контроля.
- [ ] **Покрыть субрпиксельное дрожание** — если оценка смещения битая, фильтр должен просто не супрессовать (безопасный отказ), не выдавать ложные супрессии.
- [ ] **Не затрагивать OCR счёта** — кадр-кадр не влияет на валидацию счёта; оставить как есть.

## Приоритет 3 — интеграция и проверка

- [ ] **Интегрировать в `computeOrMergeBoardDiffFromArgb`** — добавить этап после сканирования: получить delta, применить супрессию ложных срабатываний (с сохранением diffs для окклюзированных клеток и клеток с высоким delta).
- [ ] **Устойчивость к смещению и яркости** — проверить на натуральных скриншотах (смещение устройства ±2–5px, скачки яркости); фильтр не должен ухудшать FN.
- [ ] **Тестирование на реальных кадрах** — прогнать на логах Stage 10/11: сравнить число ложных diffs до/после включения фильтра (целевой диапазон: FP ↓ ≥ 10×, FN ↑ ≤ 0.1 на клетку/скан).
- [ ] **Документация в UI** — применить фильтр только в фоне; в UI оставить обычную логку «Привести к игре», без изменения поведения для окклюзированных и причинно-следственных diffs.

## Ограничения (не делать)

- [ ] Не хранить все предыдущие кадры (искры памяти).
- [ ] Не делать из pixel-delta ворота для пропуска CV-анализа клеток (риск FN при окклюзии).
- [ ] Не использовать для валидации счёта (OCR) — фильтр не видит текст шапки.
- [ ] Не перебираться в `causalHistory` — кадр-кадр живёт в отдельном, свежем keeper-е кадров.
