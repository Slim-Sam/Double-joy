# Обучение по логам: предсказание рук и улучшение алгоритма

Дата: 2026-11-28. Источник: все логи `uploads/прочитано/Лог_*.txt` (7 уникальных
сессий, 534 скана руки) + свежие Этап11 (2×132 скрина, отправлены дублем —
session.log идентичны, учтены один раз).

## Ключевой результат: рука предсказуема

* **(этап, текущая рука) → следующая рука детерминирована в ~98% случаев.**
* Энтропия: H(next)=8.50 бит → H(next|current)=**0.03 бит** — зная текущую руку,
  следующая известна практически точно.
* Из 391 пар: **381 однозначный переход**,7 конфликтов отброшено (обучение хранит
  только однозначные).
* Цвета в руках распределены равномерно (328–400 на цвет из8), длины цепочек:
  1 слой —39%,2 —56%,3 —5% (по всем сессиям).

## Что внедрено

1. **`HandTransitionsData.java`** — эмпирическая таблица переходов рук
   (381 переход), сгенерирована из логов скриптом `scripts/make_hand_transitions.py`.
   *Перегенерировать после каждого нового пакета логов:*
   `python3 scripts/make_hand_transitions.py` (затем регенер `solver.html` не нужен —
   данные в Java-исходнике, входят в компиляцию автоматически).
2. **`SolverEngine.predictNextHand(stageNo, hand)`** — точечный прогноз следующей руки
   (stage-таблица, fallback — глобальная).
3. **Look-ahead прокатка** (`evaluateRolloutLookahead`) теперь играет **ПЕРВОЙ
   предсказанную реальную руку**, и только затем синтетические выборки
   (ROLLOUT_EARLY/MID/LATE) — прокатка «видит» настоящее будущее.
4. **Кнопка «не учитывать подсказки»** — скоуп исправлен: гейт
   `useHintsInCalc` на советы режимов (SURVIVAL/DEEP) УДАЛЁН — собственные советы
   приложения работают всегда. Кнопка касается ТОЛЬКО игровых подсказок
   (🔨 молоток, 🔄 обновить, переместить столбик); их текст в расчёт не берётся
   (не парсится) по определению. Обновлены подписи и FAQ в интерфейсе.

## Тупики: что показали логи

* Тупики наступали при пустых3–6 (чаще4): рука без вариантов на оставшемся поле.
* Признаки: «зажатые» башни (walled), много3-слойных стопок, низкая
  вероятность слияния сл.руки. Уже работают: pre-deadlock совет режима,
  hammer-target advisor, STOP «пусто кл.:0».
* Следующий шаг (см. план): mergeProb считать по ПРЕДСКАЗАННОЙ руке
  (predictNextHand), а не по вероятностной модели — предупреждения о тупике
  станут точнее.

## План улучшений (следующие итерации)

1. **mergeProb по точной руке**: в computeReceptivity/STOP-советах заменить
   вероятностную модель сл.руки на predictNextHand, если переход известен.
2. **Многоходовой план с известной рукой**: цепочка hand1→hand2→hand3 из таблицы →
   планировать на2–3 хода вперёд вместо одного.
3. **Дообучение**: каждый новый пакет логов → `scripts/make_hand_transitions.py`
   → таблица растёт (сейчас381 переход; полное покрытие — все этапы/руки).
4. **Детекция ошибок по логам** (автоматически): рассинхрон счёта (СВЕРКА),
   расхождения «счёт vs экран», пустые пачки — как в анализах Этап12.
