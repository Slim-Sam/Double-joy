# Откуда игра берёт руки: изучение сервера (2026-11-28)

Цель: получить РУКИ (нижние столбики `waits`) напрямую с игрового сервера и сопоставить их
с большой таблицей переходов (`HandTransitionsData`, 694 stage + 443 global переходов).

## 1. Что уже подтверждено (разбор XAPK, `Алгоритмы_Двойная_радость.md`)

- Игра: ивент «Двойная радость» / Joy Multiplied в **Last Asylum: Plague (`com.phs.global`)**,
  Unity IL2CPP + xLua, логика мини-игры — Lua-скрипты (XOR `eyugame_lua_zombiesrpg`).
- **Руки приходят с сервера**: поле `waits` в `CardMasterStartRespS2C` и `UpdateBattle`
  (вместе с `sn, round, score, waitRound, cells, cards, refreshs, lockScoreCells, lockScoreCards`).
- Полная очередь будущих рук — `WaitBattleGenList` (генерация серверная); клиенту отдаётся
  окно из `MaxTipPosCount` (=3) слотов.
- **Штатный подсмотр**: `CardMasterViewReqC2S` → `CardMasterViewRespS2C` (режим наблюдения) —
  показывает ВСЮ очередь по порядку («сверху вниз»). Это легальный источник будущих рук.
- **Весь RNG на сервере**: у клиента нет генератора — предсказание без сервера невозможно.
- Протокол: protobuf (в Lua есть `utils_protobuf`: Field/Parser), модуль `eyGameCardMaster`,
  отправка через `MessageSend_eyGameCardMaster`, диспетчер `Dispatch`, C#-сокет
  (`SocketConnection`, `SocketByte*`, `ConnectSocketAsync` в global-metadata).

## 4. Сопоставление с большой таблицей — ГОТОВО

`scripts/compare_server_hands.py` — вход: JSON `{stage, hands:[…]}` (или `{sessions:[…]}`),
слоты серверного формата (`id_count|…`, пары `[[id,count],…]` или объекты `{id:count}`).
Выход: покрытие STAGE/GLOBAL-таблицей, точность предсказания «следующая рука», строки
`stage;handKey;nextHandKey` для новых/расходящихся переходов (готовы к
`scripts/make_hand_transitions.py`).

Самопроверка на данных самой таблицы: **694/694 переходов найдены, точность 100%, новых 0**.
