## 3. Команды для работы с GitHub (всегда использовать этот формат)

**Важно:** plain `git push` падает с `Permission denied (publickey)`. Всегда использовать `GIT_SSH_COMMAND`:

```bash
export GIT_SSH_COMMAND="ssh -i /home/user/double_joy_ssh_key -o StrictHostKeyChecking=accept-new"
```

### 3.1. Добавить и отправить изменения
```bash
cd /home/user
git add .
git commit -m "описание изменения"
GIT_SSH_COMMAND="ssh -i /home/user/double_joy_ssh_key -o StrictHostKeyChecking=accept-new" git push -u origin master
```

### 3.2. Если git не настроен
```bash
git config user.name "Slim-Sam"
git config user.email "slim-sam@users.noreply.github.com"
```

### 3.3. Проверить, что всё отправлено
```bash
git log --oneline -5
GIT_SSH_COMMAND="ssh -i /home/user/double_joy_ssh_key -o StrictHostKeyChecking=accept-new" git ls-remote origin master
```

## 5. Что сделать, если пропадает связь с GitHub

1. Проверить ключ:
   ```bash
   ssh -T -i /home/user/double_joy_ssh_key git@github.com
   ```
2. Если публичный ключ сбит — снова загнать в GitHub:
   ```bash
   cat /home/user/double_joy_ssh_key.pub
   ```
   И скопировать его в GitHub → Settings → SSH and GPG keys → New SSH key.
3. Синхронизировать workspace с GitHub:
   ```bash
   cd /home/user
   GIT_SSH_COMMAND="ssh -i /home/user/double_joy_ssh_key -o StrictHostKeyChecking=accept-new" git fetch origin
   GIT_SSH_COMMAND="ssh -i /home/user/double_joy_ssh_key -o StrictHostKeyChecking=accept-new" git pull --rebase origin master
   ```
