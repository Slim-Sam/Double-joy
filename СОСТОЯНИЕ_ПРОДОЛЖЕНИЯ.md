## 5. СЛЕДУЮЩИЕ ДЕЙСТВИЯ (если пользователь хочет продолжить анализ игры)

1. **Искать полную таблицу весов карт** в читаемых bundles:
   - Глубоко изучить `gamedata_basedb_f_zh-cn.assetbundles` (offset ~302155 уже содержит частичные веса).
   - Проверить другие bundles (`luascript_eyu_logic_datas_activity_minieliminatemasteract.assetbundles` и т.д.).
   - **Способ:** `obj.get_raw_data()` (4-byte len + UTF-8 name + 0x00 + остаток). Остаток — Lua ТОЛЬКО для языковых/gamedata баз; для `basedata_jit` — XLua bytecode (нечитаемый).
2. **Если веса не найдены:** искать XLua decompiler либо анализировать `libil2cpp.so` через `global-metadata.dat`.
3. **Сопоставить веса с данными лога** (93 руки, 286 слоёв).
4. **Смотрить этапы 11–16:** повторить эмулятор с реалистичными распределениями рук.

**Готовые зацепки:**
- Строка весов на offset ~302155 в `gamedata_basedb_f_zh-cn`: `.30 .40 .50 .60 .70 .90 .10 /10= .10 .30`.
- XLua bytecode обфусцирован 22-байтовым циклическим XOR-ключом `eyugame_lua_zombiesrpg` (key найден для расшифровки, но не привёл к readable data для `basedata_jit`).

## 7. ВАЖНЫЕ ОГРАНИЧЕНИЯ И ПРЕДУПРЕЖДЕНИЯ

- **НЕ** использовать `btnRandomHand` как истина о логике игры — это решалка, а не игра.
- **НЕ** строить APK без явного подтверждения пользователя.
- **НЕ** использовать `javac` с кириллицей без `LC_ALL=C.UTF-8` и `-encoding UTF-8`.
- **НЕ** использовать `org.json.JSONObject` внутри android.jar на desktop JVM (Throws `Stub!`).
- **НЕ** использовать CLI `unzip` с UTF-8 кириллицей — всегда Python `zipfile`.
- **НЕ** использовать `pkill -f` без исключения `os.getpid()/os.getppid()`.
- **НЕ** заменять `cx0 = 0.5 * (xLeft + xRight)` в `fitBoardCamera`; держать 540px width для ручного среза.
- Beam search (beamWidth 40, rounds 10, trials 8) **таймаутится на 300s**.
- Wave elimination: должно быть `ELIMINATE_NUM = 10`, а не `topCount >= 3`.
- **НЕ** использовать single-byte XOR на XLua bytecode.
- **НЕ** использовать direct LZ4/LZMA decompress на остатке Lua-bundle — это XLua bytecode.
- **НЕ** использовать raw `byte_start` slicing для Lua-текста — использовать `obj.get_raw_data()`.
